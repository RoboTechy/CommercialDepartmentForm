# PRT — رابط کاربری جدید (React) متصل به بک‌اند قبلی

این شاخه رابط کاربری جدید (پوشه‌ی `client/`) را به **همان بک‌اند و همان دیتابیس** سرویس PRT وصل می‌کند:
Express + SQLite (`data/app.db`) + LDAP/Active Directory + نشست ۲ ساعته + لاگ کامل تغییرات.
`docker-compose.yml` و volumeها (`./data`, `./backup`) **بدون تغییر** مانده‌اند.

## معماری
- `client/` — React/Vite. در `docker build` ساخته می‌شود (Dockerfile چندمرحله‌ای) و Express آن را از `client/dist` سرو می‌کند.
- `src/routes/apiV1.js` — API زیر `/api/v1`. همه‌ی قواعد دسترسی/قفل (دپارتمان، پیش‌نویس، لغو/عودت، ادمین محلی، بدون لاگ برای ادمین محلی، اعتبارسنجی تاریخ شمسی) سمت سرور و با همان `middleware.js`/`store.js` قبلی اعمال می‌شود؛ فرانت فقط نمایش می‌دهد.
- `src/workflow.js`, `src/extStore.js` — منطق و ذخیره‌ی ماژول گردش‌کار گسترده (مراحل، تأمین‌کنندگان، پیش‌فاکتورها، تأییدات).
- **مهر تأیید (امضای دیجیتال):** HMAC-SHA256 با کلید `SESSION_SECRET` روی (شناسه‌ی تأیید، ردیف، تأییدکننده، زمان، توضیح). سمت سرور ساخته و در هر بارگذاری دوباره راستی‌آزمایی می‌شود؛ اگر داده‌ی تأیید بعداً دستکاری شود «مهر با داده نمی‌خواند» نشان داده می‌شود. (امضای رمزنگاری‌شده با گواهی شخصی کاربر نیست.)

## تغییرات دیتابیس (فقط افزودنی)
هنگام استارت، به جدول `rows` ستون‌های `workflow_stage`, `selected_vendor_name`, `selected_quote_id`, `approvals_status`, `total_estimated_amount` و جدول‌های `vendors`, `quotations`, `approvals` با `ALTER/CREATE IF NOT EXISTS` اضافه می‌شود.
هیچ ستون یا ردیفی تغییر/حذف نمی‌شود. `workflow_stage` خالی یعنی مرحله از روی فیلدهای پرشده استنتاج می‌شود، پس ردیف‌های قدیمی بلافاصله مرحله‌ی درست دارند.
(با یک دیتابیس ساخته‌شده توسط نسخه‌ی قبلی آزمایش شد.)

## گروه‌های LDAP
گروه‌های قبلی (`PRT-*`) همان‌اند. برای تأییدات سه گروه اختیاری اضافه شد (پیش‌فرض‌ها):
`LDAP_GROUP_TECH_LEAD=PRT-TechLead`, `LDAP_GROUP_FINANCE=PRT-Finance`, `LDAP_GROUP_EXECUTIVE=PRT-Executive`.
تا این گروه‌ها در AD ساخته و پر نشوند، فقط ادمین (`PRT-Admins` / ادمین محلی) می‌تواند مراحل تأیید را امضا کند.

## اجرا
```bash
docker compose up -d --build     # همان فرمان قبلی؛ پورت‌ها ۳۰۰۱ و ۸۰
```
توسعه‌ی فرانت: `cd client && npm install --legacy-peer-deps && npm run dev` (پراکسی `/api` به `localhost:3000`).

## چه چیزهایی نسبت به رابط EJS قدیمی نیست
- ایمپورت گروهی از اکسل و خروجی اکسل سمت سرور (خروجی CSV سمت کلاینت اضافه شد). `GET /api/reports/*` (API گزارش‌گیری برای سرورهای دیگر) دست‌نخورده است.
- ویرایش درجا با دابل‌کلیک و باکس تاریخچه‌ی هر سلول.
- صفحه‌های EJS قدیمی (`views/`, `src/routes/rows.js`, `auth.js`) دیگر mount نمی‌شوند ولی در ریپو مانده‌اند؛ برگشت = اجرای پوشه‌ی نسخه‌ی قبلی.

## داده‌ی هم‌زمان
فرانت هر ۳۰ ثانیه و هنگام بازگشت به تب، داده را از سرور تازه می‌کند و بعد از هر ثبت هم بلافاصله. ثبت هم‌زمان دو کاربر روی یک فیلد «آخرین ذخیره برنده است» (مثل قبل).

## ترتیب بخش‌ها
تا بخش قبلی کامل نشده، بخش بعدی (جز ادمین) در همان ردیف چیزی ثبت نمی‌کند: درخواست‌کننده ← انبار (بلوک ۱) ← بازرگانی ← انبار (بلوک ۲).
«کامل» یعنی همه‌ی فیلدهای بخش پر باشد (به‌جز «تاریخ صدور مجوز پرداخت» وقتی مجری خرید تهران/برنا است). سرور هر ثبت را بررسی می‌کند (حتی ویرایش درجا و پیش‌فاکتور).
ادمین‌ها مستثنا هستند. برای خاموش کردن کامل: `ENFORCE_SECTION_ORDER=false` در `.env` و ری‌استارت.
